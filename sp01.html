    01 场景概览

    示例条件：夜间，车辆沿 K120 → K130 行驶。22:10 发现 K124—K126 车流异常，随后查到 K125+600 疑似货车事故占道；22:20 队尾已到 K123+800，接近上游 K123+500 弯道。

    橙色路段表示示例中的排队范围。事故位置须经证据核实；搜索机位依据覆盖范围和可用状态选择。

    阅读顺序：先看下面的处置阶段，再切换五个场景视图；每个阶段都能查看通用依据和开发记录。

    场景范围、完成条件及总体组成
    服务目标
    主动发现并查明异常，在授权范围内连续组织预警、处置调整和恢复核验。
    触发条件
    22:10，K124—K126出现车流异常；系统检查质量、施工与天气并建立H-017，无需等待明确事故报告。
    业务边界
    夜间高速公路货车疑似事故占道；异常搜索、证据补查、运营预警、清障协调及恢复核验。
    完成条件
    实际清障和通行状态已核实，剩余排队得到持续处理，措施已按权限解除，资源已释放或完成交接；未确认事项有明确承担方。
    自主协同方式
    自动查询、搜索、跟踪及获授权操作持续执行；交通管制决定、专业核查和权限外调整由相应责任主体处理。
    异常退出与交接
    超时先查询实际状态，撤回或替代前核实已执行部分；资源退出以释放或交接确认为准。
    排除事项
    不实施清障车辆自动驾驶，不代替事故调查、医疗诊断及危化品专业判断，不在事件处置过程中自行更新生产模型。

    大模型整理证据和协同条件，事件智能体持续组织行动，Skill执行可复用操作；专业服务提供检测和计算，现场系统核验后执行。

    主动发现并查找

    K124上游车流减速、下游通过量下降。异常检测同时检查数据质量、已有施工和天气信息，形成待查事件。此时事故位置和原因尚未确定。

    处理判断：先根据车流异常圈定搜索范围，再根据每次返回的画面决定继续搜索、换机位或请求现场核查。

    1. 车流检测发现异常，检查数据时效和施工、天气信息。
    2. 智能体按摄像机覆盖和当前可用状态安排搜索。
    3. 大模型结合图像分析结果整理疑点；智能体调用视频或云台 Skill 补查。
    4. 记录疑似位置、已有证据和未查明事项，继续核实。

    本阶段结果
    形成带方向、疑似区间、观测时间和证据来源的事件任务，持续跟踪未查明原因。

    异常处理及验收

    无可用机位或超过搜索时限，携带已查范围和证据缺口转交值班岗位。

    验收条件：第一机位遮挡时应继续搜索其他可用机位；无有效图像时保持未定位，不能编造事故位置。

    补查证据核实影响

    相邻摄像机在K125+600拍到货车停驶并疑似占道，遮挡导致人员及车辆状态尚不完整。

    处理判断：把疑似事故、已核实影响和待核实风险分开记录，据此选择清障资源和协同事项。

    1. 核对画面时间、行驶方向和桩号，关联占道及队尾信息。
    2. 大模型整理证据冲突和缺口，智能体安排补查。
    3. 查询车型适配、占用和预计到达时间，形成可用资源清单。
    4. 伤亡、危化品等事项交由专业力量核实；记录确认结果。

    本阶段结果
    更新疑似事故、占道范围和队尾位置，保留待核实项；避免用画面推测代替现场结论。

    异常处理及验收

    证据冲突时继续核查；专业风险未明时保留风险状态并启动相应协同。

    验收条件：旧画面不得覆盖新观测；资源已被占用时，应排除或取得明确可用承诺。

    先行预警组织处置

    已取得占道证据，队尾仍向来车方向移动。属地运营调度需要同步落实风险提示、巡查防护和适配的清障力量。

    处理判断：在有效授权内落实预警和清障安排，分别确认设施显示、工单受理和作业进度。

    1. 智能体形成 V1，核验措施范围、资源承诺及操作权限。
    2. 调用提示发布 Skill，经现场控制核验后下发至指定设施。
    3. 向清障系统提交工单，跟踪接单、出发、到场和作业条件。
    4. 大模型辅助整理协同说明；交通管制按交警有效决定执行。

    本阶段结果
    记录已显示的提示、已接收的任务及待确认事项，区分资源派出、到场和允许开始清障。

    异常处理及验收

    权限或本地控制条件不满足时拒绝相应操作，保留原因和仍在执行的有效措施。

    验收条件：工单已接收但尚未接单时不得显示已派遣；部分情报板未生效时逐目标列出并继续处理。

    跟踪风险动态调整

    队尾由K125附近回溯至K123+800，接近K123+500弯道路段；已接单清障车因既有任务延迟，原到达时间失效。

    处理判断：队尾接近上游弯道且清障延迟后，重新计算影响并调整资源，避免重复派单和无责任交接。

    1. 持续接收队尾和清障进度，发现原方案不能覆盖的风险。
    2. 智能体调用专业计算服务，大模型归纳风险及需调整的事项。
    3. 生成 V2，扩大或调整预警，重新匹配资源；必要时请求跨路段协调。
    4. 先核实原工单已执行部分，再撤回、交接或补充派遣。

    本阶段结果
    形成V2安排及变更依据，旧任务、交接状态和未完成事项继续可查。

    异常处理及验收

    跨域资源尚未承诺时持续执行本域有效措施，公开记录资源缺口和剩余风险。

    验收条件：撤回超时应查询原工单；未确认退出或交接前，不得把原资源标为空闲或下达互相冲突的替代任务。

    复核恢复分步解除

    现场报告障碍已清除，但上游仍有排队。道路可通行、排队消散和措施解除需要分别核验。

    处理判断：逐项核实道路、措施和资源的恢复状态，有未完成事项就继续跟踪或明确交接。

    1. 核实障碍是否清除、车道是否可通行、队尾是否消散。
    2. 引用有效解除决定，按目标取消提示或恢复摄像机视角。
    3. 核对工单结束、资源释放及未完成事项的接管方。
    4. 汇总事件实际结果，保存方案变化及执行证据。

    本阶段结果
    分别记录清障完成、通行恢复、提示解除及资源退出，形成可追溯的事件结案。

    异常处理及验收

    设施解除失败或资源退出未知时保留未完成项，明确继续处理或接管责任。

    验收条件：清障完成但队尾仍存在时，事件保持跟踪；解除请求已发出但无实际反馈时不得记为已解除。

    复盘验证能力改进

    H-017留下了异常触发、摄像机搜索、队尾跟踪、清障延迟和恢复核验的完整记录。

    处理判断：从本次搜索、协同和调整记录中识别缺陷，形成候选 Skill 或模型，经独立验证和批准后更新。

    1. 复盘遮挡搜索、延迟响应及无效调用，定位可复现问题。
    2. 构建候选，冻结版本、依赖和测试输入。
    3. 独立验证正常及异常用例，形成适用范围和未解决问题。
    4. 核验发布批准，逐实例确认生效；失败时按批准条件恢复。

    本阶段结果
    形成可复现的候选、验证和发布记录；运行中保持当前有效版本。

    异常处理及验收

    验证未通过或没有有效发布批准时，生产环境继续使用原有有效版本。

    验收条件：候选变化后原验证结论失效；部分实例更新失败时停止扩散，并分别保存各实例实际版本。
