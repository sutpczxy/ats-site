    CORE FEATURES

    自主运行的集成设计要求

    本页说明集成架构为支持自主运行所采用的设计要求，重点是任务如何协作执行、能力如何受控更新，以及职责与装备如何配置。

    5项共性特征
    覆盖运行、组织、演进、层级与部署

    设计要求

    01 / AUTONOMOUS OPERATION

    自运行

    在目标、权限和适用条件内持续完成状态判别、决策、现场执行和反馈，按安全要求处理异常；现场使用确认生效的模型与配置。

    02 / SELF-ORGANIZATION

    自组织

    责任主体、设施和载运工具依据任务、能力及资源状态调整协同关系，明确成员职责、承诺、交接及退出条件。

    03 / SELF-EVOLUTION

    自演进

    收集并检查运行数据，整理训练样本，改进模型。新版本通过验证并获批后部署到现场；记录所用版本和运行效果，用于下一轮改进。

    04 / MULTI-LEVEL

    跨层级集成

    国家—省市—通道/区域按实际事项配置数据提供、训练组织、验证审查、发布授权和运行监督职责，明确协调权限。

    05 / DECOUPLING

    软硬解耦

    功能、模型版本、运行实例及装备配置分别登记，通过接口与部署对应实现模型更新、功能复用和装备替换。

    自主运行与能力更新

    自主运行闭环持续执行任务；训练迭代与更新闭环利用实践数据开展训练优化，将经验证与授权的版本下发现场。数据采集、实际生效和效果反馈连接两个闭环。

    双闭环功能总图训练与运行数据关联

    自主运行对象

    本架构用两类对象说明自主运行能力：逻辑型自主单元描述职责和功能，装备型自主单元描述实现这些功能的设备。两者根据具体任务建立对应关系。

    逻辑型自主单元本架构按交通运行及其支撑职责划分的逻辑单元，在规定权限和条件下组织状态判断、决策、执行协调及反馈处理。 单元说明目标、功能、接口、权限、状态监测及异常处置要求；软件模块按功能分配与部署配置实现。
    装备型自主单元本架构中实现指定功能的物理设备或设备组合，具有明确接口，并按任务配置计算、通信、感知或控制等能力。 按装备实际能力分别说明本地控制、故障检测、安全保护及可承载功能。
    配置关系：一项逻辑功能可以分布在多台装备上，一台装备也可以承载多个逻辑型自主单元；逻辑版本、装备版本和配置关系分别管理，并通过任务、功能、装备和证据标识保持追溯。
