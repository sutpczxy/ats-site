    本架构采用上述代号登记对象描述。ODD表示自动驾驶系统的运行设计域（Operational Design Domain），在相应系统的适用条件中使用。

    标识与对应规则

    1. 组织、设备、功能、数据和关系分别设置标识。关系编号采用“模型或场景标识－类型＋序号”，例如 ATS-AL01、SP02-I01；示例仅说明格式。
    2. 公共功能先定义处理内容及输入输出，再记录逻辑单元归属和实现方式。已分配的功能可显示为 L-AUxx.Fxx；跨场景对应通过公共功能标识确定，不按相同局部序号匹配。
    3. 同一关系在多个视图中出现时保持标识一致。拆分、合并或改变端点时，保存新旧关系的对应，不因图面位置调整重排编号。
    4. 局部自主与完全自主分别管理交互编号。完整引用包含场景、配置、版本和关系编号；同一对象的身份不因配置切换而改变。
    5. 场景复用公共功能时说明适用条件和差异，不要求每个场景包含相同数量的逻辑单元、设备或功能。

    各类图表的内容

    交互概览
    参与组织、系统与设备，以及主要交互关系。
    功能详图
    功能组成、输入输出、执行顺序、依赖及异常处理；分别说明系统级协调与设备本地控制。
    接口与对应表
    接口字段、时序、条件及错误处理，以及功能、设备、职责和要求之间的具体对应。

    图面可以省略细节，但被省略的内容须在接口说明或对应表中保留，并有明确引用。

    总览集成架构数据目录场景包

    数据代号与旧编号

    D为数据描述代号，具体定义由当前数据目录登记。旧D01—D06分类及编号对应保存在历史迁移记录中。

    多层级角色与关系标识

    公共O01概括运行与变更责任，O02—O08登记国家、省市、通道/区域及监督、服务、现场的参考责任角色，见角色清单。具体机构及角色承担关系按应用登记。

    ATS-A04—A06、ATS-I32—I40、ATS-E17—E22、ATS-X21—X25为组织交互关系，沿用全站类型并独立登记端点；与原功能交互的关联见同号说明，不复用原功能关系编号表示组织间交换。

    对象目录与完整引用

    对象的完整标识由目录标识和目录内编号组成，例如ATS-REF::E-AU03、ATS-SP-02::E-AU03。公共架构登记参考对象，场景目录登记场景参与对象；场景与公共定义通过显式对应记录关联。

    同一场景的局部自主与完全自主配置保持对象身份，分别登记所选功能、权限及交互。场景功能完整引用须包含能力配置，例如ATS-SP-03::局部自主::L-AU01.F04。交互和证据引用同样包含场景、能力配置及局部编号。跨目录引用不能按相同数字后缀合并。

    公共装备配置及实际实例对应见装备身份说明。

    场景规格与架构引用

    版本 0.1.0。共同规格设计基线，待SP-02与SP-04实例验证；尚未认定旧场景符合本规格。

    场景沿用全站七类架构对象、F/D/IF/EV描述及关系类型；场景对应记录不增加架构对象或关系类别。

    公共定义、场景定义、计划配置、批准配置及实际运行记录分别登记。场景与公共定义通过显式映射关联。

    交通方式采用可扩展的适用范围，城市道路、水运、低空、高速公路等均为可配置领域。

    现场运行与能力演进分别定义状态和责任，并通过实践记录、训练来源、验证、受控发布和实际生效反馈关联。

    组织责任按国家、省市、通道/区域及实际授权范围配置；单个场景无需实例化未参与事项的层级。

    标识与配置
    内容规则
    公共引用使用ATS-REF目录及有效公共编号，携带架构版本。对象和功能不得仅按数字后缀对应。
    场景身份沿用ATS-SP-nn目录；对象身份跨配置稳定。功能、关系、数据规格、接口及证据引用携带配置标识。
    新增规格记录需求、动作、状态、参数、映射及测试用例在所属集合使用稳定id；完整定位采用包版本、配置id和集合路径。集合键不构成新的架构分类或图例。
    配置与版本配置id为稳定机器标识，显示名称可沿用局部自主、完全自主；对象是否可控、审批环节及保护条件逐项登记。版本变化保留变更记录，禁止静默重编号。
    显示编号公共关系保留ATS编号，场景关系沿用SPnn-类型nn。新增场景编号在配置及类型内连续分配，跨配置引用使用完整标识；已发布标识不因排序变化重新分配。
    五视图对应
    视图定义归属对应记录核查重点
    功能集成处理职责、输入输出及业务状态场景动作 → 场景功能 → 公共F；专用算法与公共功能的结果供给、支撑依赖分别登记输入、处理、输出及异常分支与公共职责一致；算法结果不扩大控制权限
    数据集成数据模式、身份、版本、引用及派生来源场景读写记录 → 公共D；场景字段及DR/DD约束分别登记字段类型、单位、基数、条件必填、时间语义和版本引用完整；计划与实际分开
    装备与系统集成候选承载、功能实例分配、资源与隔离场景功能实例 → 承载配置 → 参考装备形态；AL和实际D45配置分别引用承载在有效候选范围内；实例、资源、隔离和本地保护条件明确
    IT/OT集成运行环境、接口行为和受控边界场景交互 → 接口操作 → 功能端点、环境及公共关系；总线和模型服务依赖单独登记接收、执行、生效结果区分；身份、幂等、超时、恢复及部署核验完整
    组织与多层级集成事项责任、授权和管辖范围业务事项 → 主责/批准/执行/监督/接管角色 → O/H及授权记录权限有效范围覆盖操作，跨域事项双方确认；技术服务不自动取得业务批准权
    映射方式
    方式适用规则
    职责或规格细化场景行为在公共定义范围内补充具体条件，保留公共前置条件及约束。
    组合实现多个公共定义共同实现一个场景动作；分别登记成员、输入输出衔接及失败边界。
    支撑依赖登记所用公共服务及不可用影响；依赖不证明功能等价。图中使用现行DP等适用关系。
    结果供给场景算法结果由公共功能使用；算法输入、误差、适用条件及验证独立登记。
    场景扩展公共目录尚无对应项时登记专用定义、理由及审查状态；涉及公共职责缺项时提出公共定义变更。
    不适用针对具体事项及视图说明理由和审查人；不得用于省略适用的控制、状态、权限或验证约束。
    共同规格集合
    集合字段职责
    metadata 版本与来源schema_version, package_id, package_version, architecture_revision, catalog_digest, generator_version, status, source_refs固定输入及公共目录版本，记录审定依据
    sources 原始材料id, document, revision, location, excerpt, digest需求、限制和待确认项均可回溯到原文位置
    requirements 需求与边界id, source_refs, statement, goal, trigger, scope, completion, exclusions, acceptance_refs, decision_status区分原文事实、提出的解释、已确认决定及未决问题
    objects 场景对象id, object_type, name, reference_refs, role, boundary, source_refs沿用全站对象类型，跨配置保留身份
    configurations 能力与部署配置id, name, requirement_refs, loop_refs, function_refs, allocation_refs, authority_refs, interface_refs, parameter_refs每个配置独立完整，支持运行与演进关联；不按配置名称推断权限
    actions 业务动作id, configuration_id, requirement_refs, function_refs, record_refs, allocation_refs, interface_refs, authority_refs, transition_refs, test_refs作为五视图对应及开发任务检查的统一入口
    functions 功能及算法规格id, configuration_id, owner_ref, input_refs, output_refs, processing_rule, preconditions, postconditions, failure_refs, mapping_refs, algorithm_spec专用算法记录模型/方法、误差、适用范围和测试依据；其他功能显式说明algorithm_spec不适用
    records 数据规格id, configuration_id, reference_refs, schema, identity, version_rule, timestamp_semantics, constraints, retention, lineage_refs字段包括类型、单位、必填条件、枚举和引用数量，复用公共D而保留场景细化
    relations 关系记录id, configuration_id, type, source_ref, target_ref, payload_refs, condition, interface_refs, mapping_refstype从全站目录读取；消息、依赖、分配和数据引用分别按类型校验
    allocations 承载配置id, configuration_id, function_instance_ref, equipment_ref, form_ref, candidate_refs, resources, isolation, local_protection, configuration_record_ref候选、计划、批准、实际绑定分别登记；实际IP和实例可在启用配置时落实
    interfaces 接口约定id, configuration_id, relation_refs, operation, source_ref, target_ref, request_schema, result_schemas, authorization, idempotency, ordering, timeout, retry, partial_failure, recovery, evidence_refs, protocol_binding约束接收、实际执行和实际生效；适用性取决于操作类型
    authorities 事项权限id, configuration_id, action_refs, responsible_ref, approver_ref, executor_refs, supervisor_refs, takeover_ref, jurisdiction, validity, revocation, authorization_record_ref按具体事项确定权责、有效期限及越界处理
    parameters 配置参数id, configuration_id, type, unit, constraint, basis_refs, owner_ref, binding_stage, value, missing_behavior, verification_refs未定数值登记明确配置阶段及阻断条件，不能用任意默认值代替
    state_machines 状态与转换id, configuration_id, subject_ref, states, initial_state, terminal_states, transitions每条转换记录事件、守卫条件、动作、下一状态及证据；业务状态与确认状态分别维护
    mappings 五视图对应id, action_ref, view, mode, local_refs, reference_refs, rationale, inherited_constraints, added_constraints, review_status五个视图逐项形成适用或不适用结论，校验端点、方向和边界，禁止仅按名称匹配
    threads 运行与演进线程id, configuration_id, loop_kind, preconditions, action_refs, transition_refs, relation_refs, end_condition, linked_thread_refs复用状态转换定义，表达正常、退化、撤销、恢复和运行与更新闭环之间的记录关联
    evidence 验证证据要求id, configuration_id, record_refs, producer_refs, correlation_keys, purpose, integrity, access, retention定义证据要求和来源；实际执行结果另行保存，不由生成器伪造
    tests 验收用例id, configuration_id, requirement_refs, action_refs, preconditions, input, fault, expected_transitions, expected_outputs, prohibited_outputs, evidence_refs覆盖正常及适用异常分支，并检查不得发生的控制或状态结果
    issues 未决项与扩展审查id, affected_refs, question, source_refs, proposed_resolution, owner_ref, blocking_stage, status, decision, evidence_refs缺项、语义冲突和扩展审查可追踪；草稿保留问题，可实施状态禁止遗留阻断项
    场景包阅读结构
    栏目数据来源表达内容
    场景概览requirements, configurations, objects, issues目标、适用范围、完成及排除事项；主体交互概览集中呈现参与者、授权和反馈
    集成架构mappings, functions, records, allocations, interfaces, authorities五视图分别呈现整套配置；动作选择仅高亮关联内容，保持全图结构；说明默认收起
    运行机制actions, state_machines, threads, relations业务过程、状态转换及正常和异常线程，对照接收、执行、确认、撤销和恢复
    实现与验证interfaces, records, parameters, authorities, tests, evidence, requirements, issues接口、参数和验证分别设折叠目录；保留缺项处理、需求追溯及实际验证状态。共用字典、来源及历史资料置于页尾
    审定与验证状态
    状态通过条件
    规格草稿原文定位完整，结构可解析；允许保留明确标记的缺项，禁止宣称可实施
    规格审定五视图映射及所有适用行为已审查；剩余项仅为明确安排到部署阶段的参数绑定，不得遗留业务语义或安全策略缺项
    可实施配置本阶段参数与接口绑定齐全，阻断项为零，测试预期明确；表示可开发实施，不表示通过现场安全验证
    已验证配置另附指定环境、实际版本、测试结果及批准证据；生成器不得自动授予该状态
    联合核查规则
    编号核查内容要求方式
    SC01版本及身份目录版本可解析，标识唯一，所有本地及公共引用存在；输入与目录摘要固定代码
    SC02五视图覆盖每项动作对五个视图均有映射或已审查的不适用结论，输入输出及承载端点可追溯代码与专业审查
    SC03定义与扩展关系类型来自全站目录；映射保持原端点、方向、权限及适用条件，扩展理由和审查状态齐全代码与专业审查
    SC04行为完整性正常、拒绝、超时、状态未知、部分失败及恢复逐项覆盖或说明不适用；异步接收不直接转完成代码与专业审查
    SC05承载及权限候选承载、实际功能绑定及事项权限一致；现场保护与受控部署条件保留代码与专业审查
    SC06数据及接口两端模式、字段、单位、版本、幂等、重试及错误处理一致；D45、D28、D31和D46职责不混用代码与专业审查
    SC07参数与阶段缺项明确责任、依据、配置阶段及禁止动作，状态晋级不得越过阻断项代码
    SC08需求与验证每项需求有可判定的预期结果和测试，适用风险有禁止输出及证据要求代码与专业审查
    SC09图表同源图、说明、接口清单和测试索引来自同一规格，变更后重建；相同输入和工具版本生成一致结果代码
    SC10可读与可操作一级目录、缩放、高亮、条件定位及桌面和移动布局通过浏览器检查浏览器与人工审查

    场景规格与表达重构设计

    装备参考配置与实际身份

    E-AU编号标识参考装备配置；中心型、边缘型、固定设施型、载运工具型和移动型作为装备形态属性。运行目标、部署管理、数据集成和算法模型管理作为配置用途。同一实际装备可对应多个参考配置，实例以独立标识登记；角色叠加须重新核验资源、权限和故障隔离条件。
