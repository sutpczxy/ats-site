    业务交互

    关系定义与方向适用位置与示例说明
    A 目标与授权传递任务目标、批准决定或控制权限及其有效范围。

    方向：目标下达方或授权方 → 接收方

    		功能、装备、组织与多层级、IT/OT；场景交互

    示例：管理人员批准在指定路段和时段实施交通控制方案。

    		方案征求意见不具有授权效力，归I；批准后的执行指令归E。
    I 信息交换查询或提供交通状态、事件、设备状态、候选方案等业务信息。

    方向：查询方或信息提供方 → 接收方

    		功能、数据、装备、IT/OT、组织与多层级；场景交互

    示例：路侧检测设备提供流量、速度和占有率。

    		启动控制执行的服务请求归E；请求类型不能仅由接口名称确定。
    E 执行指令与反馈下发操作或控制指令，返回接收确认、执行结果及相关记录。

    方向：指令发送方或反馈方 → 接收方

    		功能、数据、装备、IT/OT、组织与多层级；场景交互

    示例：控制系统向可变信息标志发送发布指令，设备返回发布结果。

    		指令与反馈分别编号。用于事后验证的数据传输按用途分类，不能仅因称为证据就归E。
    X 异常报告与处置报告故障或运行异常，提出或执行降级、停止、人工接管和故障恢复处置。

    方向：报告方或处置要求发出方 → 接收方

    		各视图中的异常交互；场景故障处理流程

    示例：控制设备通信中断后，系统报告故障并请求处置。

    		普通设备状态查询归I；正常指令确认归E。异常处置及其结果须写明具体动作。

    结构与部署

    关系定义与方向适用位置与示例说明
    CT 系统组成说明系统、逻辑单元或设备由哪些部分组成。

    方向：整体 → 组成部分

    		对象库；功能、装备；场景系统组成

    示例：逻辑型自主单元包含状态估计功能和控制决策功能。

    		只说明组成关系，不表示组织隶属、所有权或管理权限。
    OS 组织隶属说明组织或岗位所属的组织。

    方向：下属组织或岗位 → 所属组织

    		组织与多层级；场景参与组织

    示例：运行监控岗位隶属于相应运行管理机构。

    		按实际组织设置描述，项目层级名称不能作为隶属关系的依据。
    AL 功能分配说明一项功能由哪个系统或设备实现。

    方向：功能 → 实现该功能的系统或设备

    		功能、装备、IT/OT；场景功能分配

    示例：交通状态估计功能由边缘计算设备实现。

    		不规定具体软件版本或安装位置；部署另用DE表示。
    DE 软件部署说明软件或模型服务实例安装、运行在哪个计算节点。

    方向：软件或服务实例 → 计算节点

    		装备、IT/OT；场景部署配置

    示例：交通预测服务的指定版本部署在边缘计算节点。

    		分别记录软件制品、服务定义、运行实例和计算节点，通过标识及版本建立部署对应。
    RS 职责分工说明组织或人员负责的审批、运行、操作、维护或监督事项。

    方向：组织或人员角色 → 负责的事项

    		组织与多层级；各视图职责表、场景权责表

    示例：运行管理机构负责交通控制方案审批，运维岗位负责设备维护。

    		职责分工不同于一次批准或指令；具体权限和责任依据另行说明。
    LK 通信连接说明系统或设备接口之间的通信通道。

    方向：接口 — 接口；单向通道注明方向

    		装备、IT/OT；数据交换通道、场景通信配置

    示例：边缘计算节点经通信网络连接路侧控制设备。

    		通信配置记录通道及协议；数据质量和控制权限由接收功能分别校验。

    功能与行为

    关系定义与方向适用位置与示例说明
    DP 依赖说明功能或系统需要使用的服务、数据或资源。

    方向：使用方 → 所依赖的服务、数据或资源

    		功能、数据、装备、IT/OT；场景运行条件

    示例：控制权限校验需要身份认证服务和权限配置。

    		记录不可用时的处理；依赖关系不表示活动执行先后。
    CF 活动顺序说明活动之间的执行顺序，以及分支、并行和汇合条件。

    方向：前序活动 → 后继活动

    		功能；IT/OT控制流程；场景运行与演进流程

    示例：完成方案验证后提交审批，验证未通过则修改方案。

    		活动名称应为具体处理动作；状态变化另用ST表示。
    ST 状态转换说明对象由一个状态转换到另一个状态的事件和条件。

    方向：原状态 → 后继状态

    		功能、IT/OT；设备、任务及发布过程的状态模型

    示例：设备从正常状态转为故障状态，修复并通过自检后恢复正常。

    		状态转换不代替故障报告消息；报告和处置交互另用X表示。

    要求与对应

    关系定义与方向适用位置与示例说明
    CN 约束说明适用条件、性能指标或安全要求对设计内容的限制；条件可由记录或资源与环境对象的属性给出。

    方向：条件、要求或提供约束条件的资源与环境对象 → 受限制的功能、设备或接口

    		特征要求、五类视图、对象库；场景适用条件

    示例：车道控制功能使用前须确认检测数据有效，并满足规定的响应时间要求。

    		具体阈值应注明依据；系统范围和组织权限分别描述。
    TR 功能对应说明场景功能与公共功能之间的对应，包括拆分、组合及差异。

    方向：场景功能 → 公共功能

    		公共功能目录与场景功能表

    示例：场景的瓶颈识别功能对应公共模型中的交通状态分析功能。

    		对应不表示类型实例化；端点、输入输出及差异须分别记录。
    IN 实例化说明具体设备、软件实例或数据记录所属的类型。

    方向：实例 → 类型定义

    		对象库、数据、装备；场景实例目录

    示例：某一条交通事件记录属于交通事件数据类型。

    		类型规定共性结构；实例具有独立标识，并记录实际属性与配置。
    RF 功能分解将一项功能分解为较具体的子功能，并说明各子功能的作用。

    方向：父功能 → 子功能

    		功能视图；公共及场景功能分解

    示例：交通状态分析分解为数据校验、状态估计和拥堵识别。

    		与CT的单元组成不同；父子端点均为功能，不以分解箭头表示执行顺序。
    VE 验证对应说明测试用例或验证结果针对的要求，并记录判定方法和结论。

    方向：测试用例或验证结果 → 被验证要求

    		功能、IT/OT；测试与场景验证

    示例：指令响应时间测试结果关联相应性能要求。

    		分别保存测试条件、测量结果、判定依据和结论；通过状态由判定结果确定。

    数据关联

    关系定义与方向适用位置与示例说明
    DR 数据引用

    Data Reference

    		数据记录通过标识及必要的版本字段引用另一数据记录；应说明引用字段、基数和适用条件。

    方向：引用记录 → 被引用记录

    		数据集成视图；场景数据定义、记录关联与版本追溯

    示例：执行记录通过command_id引用原控制指令记录。

    		引用记录保存目标标识及必要版本；消息传递、处理顺序、访问权限和内容副本分别配置。
    DD 数据派生

    Data Derivation

    		数据经过筛选、转换、聚合或计算形成其他数据，记录输出所依据的输入、处理方法及版本。

    方向：派生数据 → 来源数据

    		数据集成视图；质量处理、样本构建、模型训练及场景数据追溯

    示例：样本数据集关联实际用于采样的交通观测记录，另记筛选、脱敏和标注过程。

    		箭头沿来源追溯方向表达。派生关系须记录输入、处理方法及输出；报告查阅采用DR引用关系。

    多层级组织交互

    国家、省市、通道/区域的组织交互使用A、I、E、X类型。正式关系及条件见组织关系清单。组织关系的端点为责任主体，功能交互的端点为执行相应处理的单元或功能，两者通过职责说明对应。

    五类装备形态的功能分配

    中心型、边缘型、固定设施型、载运工具型和移动型按典型配置表达。AL登记具体功能到装备参考配置的条件分配，I登记能力状态反馈，见装备功能分配与反馈清单。参考配置可组合，实际装备数量及实例分别登记。
